# 下一阶段实验与门槛

## P0：资源和身份
- 验证 XEX 可选头、执行身份、压缩/加密标志与导入表边界；不输出密钥。
- 对两个不同 XEX 分别建立分析输入，不以同名同大小互换。
- 研究 Coalesced.int/jpn/kor 的结构与实际语言覆盖，输出稳定 ID 的最小可复现文本样本。
- 核对 UE3 版本字段、压缩块、name/import/export 表，建立资源引用图与跨盘依赖证据。

## P1：两条路线对等最小实验
- A：固定工具 commit，先记录 XEX 载入、代码分析、代码生成、Windows 编译四个独立结果；再评估启动诊断。
- B：固定 UE3 格式解析器，证明一个包的对象/脚本/原生函数引用覆盖；再估计合法运行时缺口。
- 对两条路线设停止条件：无法建立可靠输入身份/结构或缺少关键实现时保留失败日志，不假装成功。

## P2：本地化 PoC
实际文本往返、控制码保留与字形覆盖通过后，测试少量中文、换行和长文本；人工审核后才扩展翻译规模。
最终路线决策依据实验指标，不依据“已有其他游戏成功”作无条件推断。
